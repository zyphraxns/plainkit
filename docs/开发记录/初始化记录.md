### 3.2 已解决的技术问题（记录备查）

**TypeScript 必须锁 6.x，不能用 7.x。** TS 7 的原生编译器不暴露 `astro check` 依赖的 programmatic API，装上后 `npm run typecheck` 直接报错退出。`@astrojs/check@0.9.10` 的 peer 要求是 `^5.0.0 || ^6.0.0`。

**`astro.config.mjs` 必须设 `inlineStylesheets: 'never'`。** Astro 默认会把小于 4KB 的样式表内联成 `<style>`，而我们的 CSP 是 `style-src 'self'`（不含 `unsafe-inline`）——内联样式会被浏览器拦掉，表现为**线上页面完全没有样式，而本地开发环境完全看不出问题**。

**`tsconfig.json` 不能用 `baseUrl`。** 它在 TS 6/7 已废弃，直接报 `TS5101`。不写 `baseUrl` 时 `paths` 按 tsconfig 所在目录解析，行为一致。

**`vitest.config.ts` 需要 `/// <reference types="vitest/config" />`。** 否则 `getViteConfig` 的返回类型不认识 `test` 字段，报 `TS2353`。

**性能门禁脚本的外部域名扫描只扫「会发起请求的位置」，不扫散文。** About 页说明文字里写着 `http://localhost:8080`（自托管地址），全文扫描会把它误判成外部请求。一个天天误报的门禁最终会被关掉，那比没有门禁更糟。
