# 二维码生成器（qr-code） — 功能需求说明书

> 工具 7（产品编号）。slug `qr-code`，四处命名必须一致：
> URL 路径 = `src/pages/tools/qr-code/` = `src/lib/tools/qr-code/` = `specs/features/qr-code.md`。
>
> 定稿时间：2026-09-24

## 1. 背景与价值

**为什么做**：二维码是极少数「产物天然要被印出去 / 贴出去 / 发给别人」的东西——店里的 Wi-Fi 码、名片上的联系方式、海报上的活动链接。它是留存型工具，与 ASCII 的「一次性玩具」互补。隐私牌也最硬：Wi-Fi 密码、手机号、私人链接，没人想传到别人服务器上。

**竞品核实（2026-09-24，3 组关键词 + 候选池当日扫描）**：赛道**极度饱和**，且竞品已普遍做到「浏览器本地生成 + 无注册 + 无水印 + PNG/SVG」——ToolifyHub（2026-09 更新）、ToolForge（2026-08）、Kodotools（2026-07）、tooleem（2026-05）、qr-code-generator.com。头部堆料严重：9–10 种内容类型、logo 嵌入、ECC L/M/Q/H、自由配色、256–2400px、打印尺寸计算器、扫码评分。

**裁决逻辑**：不做「功能比竞品多」——那条路打不赢也不符合本项目的克制定位。能打的只有两条：①**产物即内容**（二维码本身就是要发出去的东西）②**省事**（竞品给你 20 个选项，我们给 3 个决策：选类型、填内容、下载）。内容类型**对齐竞品**（用户 2026-09-24 裁定），因为它同时是**发现性入口**——普通人不知道二维码能干什么，看到「Wi-Fi / 名片 / 电话」这些标签才知道有用。但样式与导出**严格封顶**。

**做成什么样**：选类型 → 填字段 → 即时出码 → 下载 PNG / SVG 或直接复制图片。全程本地生成，输入内容一个字节都不出设备。

**关联**：`产品概述.md` §6.2 工具 7（2026-09-24 增补）；`工具候选池.md` 第一节；开发顺序第 6 位（1 → 2 → 4 → 5 → 6 → 7）。

**证伪条件**：上线发帖两周内零分享 / 零回流 → 「产物即内容」假设在二维码这个类目不成立（记录于 `工具候选池.md`）。

## 2. 范围

### 本次做

- **7 种内容类型，一行平铺标签**（不下拉——下拉就丢掉了发现性）：链接 / 文本 / Wi-Fi / 名片 / 邮件 / 电话 / 短信
- 每种类型一个极简表单，**字段数封顶**：
  | 类型 | 字段 | 必填 |
  |---|---|---|
  | 链接 Link | 网址（单行） | 是 |
  | 文本 Text | 内容（多行） | 是 |
  | Wi-Fi | 网络名、密码、加密方式（WPA / WEP / 无，默认 WPA） | 网络名 |
  | 名片 Contact | 姓名、电话、邮箱、公司、网址 | 姓名 |
  | 邮件 Email | 收件人、主题、正文 | 收件人 |
  | 电话 Phone | 号码 | 是 |
  | 短信 SMS | 号码、预填内容 | 号码 |
- **输入即时生成**，无「生成」按钮
- **4 个预设深色**（中性黑 / 深蓝 / 深绿 / 深红，取设计令牌的深色），背景恒为白
- **可查看实际编码内容**（折叠区，可复制）+ 显示码的规格（版本号 / 模块数 / 纠错等级）——**这是不扫码也能验证对错的手段**
- 导出 **PNG（512 / 1024 两档）** + **SVG（矢量，打印无损）** + **一键复制图片到剪贴板**
- 产物（PNG / SVG）二维码下方留白处带一行 `PlainKit` 小字（§6.1 回流闭环）
- 空状态预填一个示例（链接 → `https://zyphraxns.github.io/plainkit/`），打开即看到一张码

### 本次不做

- **纠错等级（ECC）选项** — 固定 M 级（15%）。H 级只在中间盖 logo 时才有意义，而我们不做 logo；L 级不适合打印
- **logo 嵌入 / 渐变 / 圆角点阵 / 自定义点样式** — 纯装饰，且每一项都降低扫码可靠性
- **自由取色器、自定义背景色** — 用户会配出扫不出来的低对比度码，与「省事」定位相悖
- **打印尺寸计算器、扫码成功率评分** — 堆料，对能否扫出零影响
- **PDF / 地理位置 / 社交主页 / 文件类二维码** — PDF 与文件二维码本质是「一个链接」，用链接类型即可；定位需要外链地图服务
- **二维码识别 / 解码（上传图片反解内容）** — 图像识别，成本高，且与「生成」是两个工具
- **批量生成、历史记录、收藏** — 违反 BR-006 的隐私决策（不保存任何输入）
- **动态码 / 短链 / 扫码统计** — 需要后端与跳转服务，违反纯静态底线
- **AI 增强** — 二期，且须满足「结果可被验证」

## 4. 需求详述

### 4.1 核心流程

1. **进入页面** → 空状态已预填示例（链接 → `https://zyphraxns.github.io/plainkit/`），右侧直接显示一张码，导出按钮全部可用
2. **选类型** → 点一行平铺标签之一，表单换成该类型的字段；切换类型时各类型各自的输入互不覆盖
3. **填内容** → 边填边出码，无需点任何按钮
4. **微调（可选）** → 点一个预设深色
5. **验证（可选）** → 展开折叠区看实际编码内容与码的规格
6. **导出** → 下载 PNG（512 或 1024）、下载 SVG、或直接复制图片

### 4.2 交互规则

- 必填字段为空时**不生成码**，结果显示区给出引导性提示（如「输入网址后这里会出现二维码」），导出按钮置灰
- 内容变化时预览即时刷新，**不设「生成」按钮**
- 内容超出二维码容量时显示明确提示与上限数字，**绝不静默截断**（静默截断 = 用户拿到一张扫出来内容缺一半的码，是最坏的失败）
- Wi-Fi 密码默认以密文显示，旁边一个「显示」开关
- 复制图片在浏览器不支持或非安全上下文时，提示「改用下载」，不静默失败
- 载入失败 / 生成失败时，已有的码保持不变，不把结果区清空

### 4.3 业务规则

| 编号 | 规则 |
|------|------|
| BR-001 | **全程本地**：编码、渲染、导出全在浏览器完成，不发出任何携带用户输入的网络请求，输入内容不出设备 |
| BR-002 | **产物带站点标识**：PNG / SVG 的二维码下方留白处带一行 `PlainKit` 小字，不影响扫码（§6.1 回流闭环） |
| BR-003 | **静区强制 4 个模块**：所有导出形态（页面预览 / PNG / SVG）四周留白 ≥ 4 个模块宽度。静区不足是扫码失败的第一大原因 |
| BR-004 | **纠错等级固定 M 级（15%），不提供选项**；版本自动选「能装下内容的最小版本」。同一内容每次生成的矩阵完全一致（确定性） |
| BR-005 | **四底线**：无注册、无广告、无追踪、零第三方脚本 |
| BR-006 | **不保存任何输入**：不使用任何本地存储；刷新页面回到示例态，不残留用户填过的 Wi-Fi 密码 / 手机号 / 私人链接 |
| BR-007 | **编码格式遵循通用扫码约定**：Wi-Fi 用 `WIFI:T:...;;`、名片用 **vCard 3.0**（不用 MECARD——它是日本 DOCOMO 的老格式，iOS 支持差）、邮件用 `mailto:`、电话用 `tel:`、短信用 `sms:<号码>?body=<内容>`（iOS 与现代 Android 都认这个写法） |
| BR-008 | **封顶**：内容类型 ≤ 7 种，每种类型字段 ≤ 5 个。任何新增都要先过这条 |

## 5. 验收标准

### 5.1 正常流程 (Happy Path)

- [ ] **AC-001**: 空状态示例
  - **Given** 用户首次打开工具页
  - **When** 页面加载完成
  - **Then** 已预填示例内容（链接 → `https://zyphraxns.github.io/plainkit/`）并显示一张可扫的码，下载 PNG / 下载 SVG / 复制图片三个按钮均可用

- [ ] **AC-002**: 七种类型平铺切换
  - **Given** 用户在工具页
  - **When** 用户点击「链接 / 文本 / Wi-Fi / 名片 / 邮件 / 电话 / 短信」任一标签
  - **Then** 表单切换为该类型的字段（字段表见 §2）；七个标签**同时可见**（不是下拉菜单）；切回先前类型时，该类型之前填的内容仍在

- [ ] **AC-003**: 输入即时生成
  - **Given** 用户在任一类型的表单中输入内容
  - **When** 内容发生变化
  - **Then** 二维码即时刷新，**不出现「生成」按钮**，无需额外点击

- [ ] **AC-004**: 链接自动补协议
  - **Given** 用户选择「链接」类型
  - **When** 用户输入 `PlainKit`（不含协议头）
  - **Then** 生成指向 `https://zyphraxns.github.io/plainkit/` 的码，并在输入框下方显示一行说明「已自动加上 https://」；输入已含 `https://` 或 `http://` 时不再补

- [ ] **AC-005**: 长文本
  - **Given** 用户选择「文本」类型
  - **When** 用户输入一段多行长文本（含换行）
  - **Then** 正常生成，扫码后得到的内容与输入一致（换行保留）

- [ ] **AC-006**: Wi-Fi 码可连
  - **Given** 用户选择「Wi-Fi」，填入网络名与密码，加密方式选 WPA
  - **When** 生成后用手机扫描
  - **Then** 手机提示「加入该 Wi-Fi 网络」，网络名与密码与输入一致，可直接连上；加密方式选「无」时生成的是开放网络凭据

- [ ] **AC-007**: Wi-Fi 密码默认隐藏
  - **Given** 用户在 Wi-Fi 表单输入密码
  - **When** 查看密码框
  - **Then** 密码默认密文显示；点击「显示」后明文可见，再点恢复密文

- [ ] **AC-008**: 名片码可存入通讯录
  - **Given** 用户选择「名片」，填姓名（必填）+ 电话 / 邮箱 / 公司 / 网址
  - **When** 生成后用手机扫描
  - **Then** 手机提示「添加到通讯录」，各字段与输入一一对应，不丢字段、不错位

- [ ] **AC-009**: 邮件码
  - **Given** 用户选择「邮件」，填收件人 + 主题 + 正文
  - **When** 生成后用手机扫描
  - **Then** 打开邮件客户端，收件人 / 主题 / 正文与输入一致

- [ ] **AC-010**: 电话码
  - **Given** 用户选择「电话」，填入号码
  - **When** 生成后用手机扫描
  - **Then** 手机提示拨打该号码，号码与输入一致

- [ ] **AC-011**: 短信码
  - **Given** 用户选择「短信」，填入号码与预填内容
  - **When** 生成后用手机扫描
  - **Then** 打开短信应用，收件号码与预填内容与输入一致

- [ ] **AC-012**: 颜色预设
  - **Given** 已生成一张码
  - **When** 用户点击四个深色预设之一（中性黑 / 深蓝 / 深绿 / 深红）
  - **Then** 码的前景色立即变为该色，**背景恒为白色**；四种颜色肉眼可辨不同；不出现自由取色器

- [ ] **AC-013**: 编码内容可查看
  - **Given** 已生成一张码
  - **When** 用户展开结果下方的折叠区
  - **Then** 看到**实际编码进二维码的字符串**（如 `WIFI:T:WPA;S:Cafe;P:1234;;`），可一键复制；同时显示码的规格：版本号、模块数、纠错等级

- [ ] **AC-014**: 导出 PNG
  - **Given** 已生成一张码
  - **When** 用户选择 512 或 1024 并点击下载 PNG
  - **Then** 得到对应像素尺寸的正方形 PNG，模块边缘锐利无模糊、无压缩噪点，四周有静区（BR-003），下方带 `PlainKit` 小字（BR-002），文件名形如 `qrcode-wifi.png`

- [ ] **AC-015**: 导出 SVG
  - **Given** 已生成一张码
  - **When** 用户点击下载 SVG
  - **Then** 得到矢量 SVG，放大到任意尺寸模块边缘依然锐利，四周有静区（BR-003），下方带 `PlainKit` 小字（BR-002）

- [ ] **AC-016**: 复制图片
  - **Given** 已生成一张码，浏览器支持图片剪贴板且在安全上下文下
  - **When** 用户点击复制图片
  - **Then** 图片进入系统剪贴板，可直接粘贴进聊天窗口 / 文档；并显示复制成功的反馈

- [ ] **AC-017**: 产物带站点标识 ← BR-002
  - **Given** 用户导出 PNG 或 SVG
  - **When** 打开导出的文件
  - **Then** 二维码下方留白处有一行小字 `PlainKit`，位置在静区之外，**不影响扫码**

### 5.2 边界与异常 (Edge & Error Cases)

- [ ] **AC-018**: 必填为空 / 纯空格
  - **Given** 用户切换到任一类型且必填字段为空（或只输入了空格）
  - **When** 查看结果区
  - **Then** 不生成码，显示引导性提示（如「输入网址后这里会出现二维码」），三个导出按钮置灰不可点，不产出空白/无效码

- [ ] **AC-019**: 内容超出容量
  - **Given** 用户输入的内容超过二维码在该纠错等级下能容纳的上限（如粘贴一整篇文章、或超长网址）
  - **When** 生成
  - **Then** 显示明确提示「内容过长，二维码最多容纳约 N 个字符，请缩短」（N 为实际上限数字），**不静默截断、不输出一张内容缺一半的码**

- [ ] **AC-020**: 中文与 emoji
  - **Given** 用户输入含中文或 emoji 的内容
  - **When** 生成后用手机扫描
  - **Then** 扫码后显示的文字与输入完全一致，不出现乱码或问号

- [ ] **AC-021**: Wi-Fi 特殊字符
  - **Given** 用户的 Wi-Fi 网络名或密码含 `;` `:` `\` `,` 等特殊字符
  - **When** 生成后用手机扫描
  - **Then** 手机读到的网络名与密码与输入**逐字符一致**（特殊字符被正确转义，未被当作分隔符截断），可正常连上

- [ ] **AC-022**: 名片特殊字符
  - **Given** 用户的姓名或公司名含 `,` `;` `\` 等特殊字符
  - **When** 生成后用手机扫描
  - **Then** 通讯录里显示的姓名 / 公司与输入逐字符一致，字段不被拆错

- [ ] **AC-023**: 电话号码格式
  - **Given** 用户输入的号码含空格（如 `+49 30 123456`）
  - **When** 生成后用手机扫描
  - **Then** 拨号提示显示的号码为 `+4930123456`（空格被去除，`+` 与 `-` 保留）

- [ ] **AC-024**: 邮件主题或正文留空
  - **Given** 用户选择「邮件」，只填了收件人
  - **When** 生成后用手机扫描
  - **Then** 正常打开邮件客户端且收件人正确，主题与正文为空，**不报错、不要求补齐**

- [ ] **AC-025**: 复制图片不被支持
  - **Given** 用户的浏览器不支持图片剪贴板，或页面不在安全上下文下
  - **When** 用户点击复制图片
  - **Then** 显示提示引导改用「下载 PNG」，**不静默失败**（不能点了没反应）

- [ ] **AC-026**: 移动端完整流程
  - **Given** 用户在手机浏览器打开工具页
  - **When** 完成选类型 → 填字段 → 换色 → 查看编码内容 → 下载 PNG 的全流程
  - **Then** 七个类型标签排布不溢出屏幕、键盘弹出不遮挡输入框、码的预览清晰、按钮均可点、页面无横向滚动

### 5.3 业务规则验证 (Business Rules)

- [ ] **AC-027**: 纯本地处理 ← BR-001
  - **Given** 用户使用本工具的任何功能（含输入 Wi-Fi 密码、生成、换色、导出、复制）
  - **When** 观察网络请求
  - **Then** 不发出任何携带用户输入的网络请求，输入内容不出设备

- [ ] **AC-028**: 静区强制 4 模块 ← BR-003
  - **Given** 用户查看页面预览，或导出 PNG / SVG
  - **When** 观察码的四周
  - **Then** 四周留白宽度 ≥ 4 个模块，三种形态一致

- [ ] **AC-029**: 纠错等级固定 M、版本自动最小 ← BR-004
  - **Given** 用户输入同一段内容
  - **When** 查看折叠区显示的规格
  - **Then** 纠错等级恒为 M；版本号为「能装下该内容的最小版本」；**界面上不存在纠错等级选项**；重复生成（刷新后填同样内容）矩阵完全一致

- [ ] **AC-030**: 不保存任何输入 ← BR-006
