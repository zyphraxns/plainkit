**与 s4 模板的偏差（都是有意为之）**：

1. **没有顶层 `tests/` 目录**——测试与逻辑**同目录**（`index.test.ts` 紧挨 `index.ts`）。理由：「加了逻辑但没加测试」这件事在目录里肉眼可见，比集中放一起更难糊弄过去。
2. **没有 `src/modules/`**——Astro 的约定是 `src/pages/`（路由）+ `src/lib/`（逻辑），沿用框架约定而不是硬套模板的分层名。
3. **`.env.example` 几乎是空的**——本项目无后端、无密钥，只有两个构建期变量（见第 2 节）。填一堆假的环境变量反而误导。

## 2. 关键文件说明 (Key Files)

| 文件 | 说明 |
|---|---|
| `package.json` | `dependencies` **必须永远为空**，所有依赖在 `devDependencies`。脚本：`dev` / `build` / `preview` / `test` / `typecheck` / `format` / `format:check` |
| `package-lock.json` | 必须提交。CI 用 `npm ci`，不用 `npm install` |
| `astro.config.mjs` | `output: 'static'`；`site` 填正式域名；`base` 从环境变量 `BASE_PATH` 读（Cloudflare 用 `/`，GitHub Pages 用 `/<repo>/`）；`trailingSlash: 'always'`；**不装任何 SSR 适配器** |
| `tsconfig.json` | `extends: "astro/tsconfigs/strictest"`；路径别名 `@/*` → `src/*` |
| `vitest.config.ts` | 用 `astro/config` 的 `getViteConfig`；`environment: 'node'` |
| `.nvmrc` | `24`。Cloudflare Pages 构建环境变量同步设 `NODE_VERSION=24` |
| `.env.example` | 只有两个**构建期**变量：`BASE_PATH`、`NODE_VERSION`。本项目**没有**运行时环境变量、没有密钥 |
| `.prettierrc` | 含 `prettier-plugin-astro`；`singleQuote: true`、`printWidth: 100` |
| `nginx.conf` | 自托管镜像：静态服务 + 目录式 URL 回退（`/tools/x/` → `/tools/x/index.html`）+ 长缓存资源 |
| `Dockerfile` | 多阶段：Node 构建 → `nginx:alpine` 托管 `dist/` |
| `docker-compose.yml` | `docker compose up` 一键起本地静态站 |
| `Dockerfile` / `nginx.conf` | 存在的唯一目的：满足「可自托管」这条产品承诺 |
| `README.md` | 项目入口文档，**必须包含「如何启动」**（`npm install && npm run dev`）与「如何自托管」（`docker compose up`） |
| `.github/workflows/ci.yml` | 四步串行：`format:check` → `typecheck` → `test` → `build`。**任一失败不允许合并** |
| `.github/workflows/deploy-pages.yml` | 构建后发布到 GitHub Pages 镜像（`BASE_PATH=/<repo>/`） |
| `LICENSE` | Apache-2.0 完整全文（约 11,000 词），版权行 `Copyright 2026 liamqiu`。**不能简写、不能自己概括** |
| `NOTICE` | 默认不创建。仅当依赖树里出现 Apache-2.0 的包时，才把它的 NOTICE 内容合并进来 |

## 3. 模块说明 (Module Description)

### 3.1 `src/lib/` —— 纯逻辑层（**本项目最重要的架构边界**）

> **红线：`src/lib/` 下的任何文件都不允许出现 `document` / `window` / `navigator` / `localStorage`，也不允许出现任何网络请求。**

理由（这一条同时买到两样东西）：

1. **TDD 变便宜** —— 纯函数测试毫秒级完成，不需要浏览器、不需要 DOM 模拟
2. **用户能不读代码就验收** —— 逻辑可以被单独喂输入、单独看输出

| 目录 | 内容 |
|---|---|
| `src/lib/tools/<slug>/` | 单个工具的纯计算逻辑。每个工具一个目录 |
| `src/lib/shared/date/` | 日期计算内核。**工具 2（倒计时）和工具 4（日期时长）共用**——它们是同一套日期数学的两个界面 |
| `src/lib/shared/url-state/` | 把工具状态编解码进 URL query 参数。这是「可复制链接」这个可分享产物的技术基础 |
| `src/lib/shared/canvas-card/` | Canvas 卡片绘制内核。**工具 2 和工具 5 共用**（都产出可下载的图） |
| `src/lib/shared/format/` | 数字与文本格式化（有效数字、千分位、工作日计数等） |

**`canvas-card` 的硬性要求**：必须基于 `measureText` 做自适应排版（先测文字宽度再决定换行与字号），**不能按固定像素绝对定位**。原因见 `技术栈.md` §3.4——本项目用系统字体栈，不同机器的字体宽度不同，写死坐标会渲染出溢出的卡片。

### 3.2 `src/pages/` —— 路由层（只做三件事）

1. 用 `<BaseLayout>` 包住页面，传齐它要求的 props
2. 渲染表单与结果区域（结构用 `.astro`，样式用 scoped `<style>`）
3. 用一小段 `<script>` 把 DOM 上的值交给 `src/lib/`，再把结果画回去

**禁止**：在 `src/pages/` 里写任何计算公式。看到一个页面文件里有算式，就是放错地方了。

### 3.3 `src/components/` —— 共享 UI

只放**被 2 个以上工具用到**的组件。只有一个工具用的结构，直接写在该工具的页面文件里。

### 3.4 新增一个工具要动的地方（照这个清单做，不要漏）

```
1. specs/features/<slug>.md               # 需求文档（由 s8 产出）
2. src/lib/tools/<slug>/index.test.ts     # 先写测试（TDD 的 RED 阶段）
3. src/lib/tools/<slug>/index.ts          # 纯逻辑
4. src/pages/tools/<slug>/index.astro     # 页面（照 DESIGN.md §6-bis.5 的模板填）
5. src/lib/shared/tools.ts                # 在 TOOLS 登记表里加一行（首页索引读它）
```

**不需要**改 `astro.config.mjs`（文件路由自动生效）、不需要注册路由、不需要改任何配置。
**不需要**改 `src/pages/index.astro`——首页从登记表读，加一个工具只需要在 `tools.ts` 里加一条。

## 4. 文件放置规则 (Placement Rules)

| 要放的东西 | 放哪 |
|---|---|
| 页面 / 路由 | `src/pages/`，一个文件 = 一个 URL |
| 计算公式、解析、校验逻辑 | `src/lib/tools/<slug>/`，**禁止直接写在 `.astro` 页面里** |
| 被 2 个以上工具复用的纯逻辑 | `src/lib/shared/` |
| 被 2 个以上工具复用的 UI | `src/components/` |
| 设计 token（颜色、间距、字号） | `src/styles/tokens.css`，**具体数值由 `DESIGN.md` 定死** |
| 工具私有样式 | 该工具 `.astro` 文件里的 scoped `<style>` |
| 图片、图标、字体（本项目无字体） | `public/` |
| 过程记录（初始化、阶段报告、bug 报告） | `docs/` |
| 规格定义（产品/技术/结构/规范/AC） | `specs/` |

## 5. 依赖方向（**不可违反**）

```
src/pages/**  ──▶ src/components/**  ──▶ src/lib/**  ──▶ (无外部运行时依赖)
     │                    │                  │
     └────────────────────┴──────────────────┘
              允许的方向：从左往右
```

**合法**：

- `src/pages/` 可以 import `src/components/`、`src/lib/`
- `src/components/` 可以 import `src/lib/`
- `src/lib/tools/*` 可以 import `src/lib/shared/`

**禁止**：

| 禁止的依赖 | 为什么 |
|---|---|
| `src/lib/**` → `src/pages/**` / `src/components/**` | 逻辑层反向依赖界面层，TDD 立刻失效 |
| `src/lib/tools/A/` → `src/lib/tools/B/` | 工具之间不能互相依赖。需要共用就下沉到 `src/lib/shared/` |
| `src/lib/shared/` → `src/lib/tools/**` | 共享层反向依赖具体工具 |
| 任何 `src/lib/**` 文件引用 `document` / `window` / `navigator` | **破坏 TDD 与「纯本地确定性计算」两条底线** |
| 任何文件引用项目外部域名（字体 CDN、分析脚本等） | 违反「零第三方脚本 / 零追踪」 |

> 最后两条由 `DESIGN.md` 定义具体的检查方式（本地命令 + CI 门禁）。

## 6. 命名约定速查

| 元素 | 风格 | 示例 |
|---|---|---|
| 工具 slug | `kebab-case` | `grade-calculator` |
| 逻辑文件 | `index.ts`（目录内） | `src/lib/tools/grade-calculator/index.ts` |
| 测试文件 | `<模块>.test.ts`，与模块同目录 | `index.test.ts` |
| Astro 页面 | `index.astro`（目录内，对应目录式 URL） | `src/pages/tools/grade-calculator/index.astro` |
| Astro 组件 | `PascalCase.astro` | `ToolShell.astro` |
| 纯函数 | `camelCase`，动词开头 | `computeWeightedAverage()` |
| 常量 | `SCREAMING_SNAKE_CASE` | `MAX_SUBJECTS` |
| 类型 | `PascalCase` | `CourseGrade` |
| URL 路径 | `kebab-case`，目录式带尾斜杠 | `/tools/grade-calculator/` |

**完整命名规范（含 lint 规则与正反示例）由 `DESIGN.md` 定义。**
