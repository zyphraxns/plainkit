# PlainKit · 工具候选池

> 后续工具的候选调查与裁决记录。每个候选入库前必须过两道门：
> ①**可分享产物门槛**（产品概述 §6.1——做完没人会发出去的不做）②**四条底线**。
> 竞品扫描日期：2026-09-24。本档案是候选池的唯一事实来源，新候选先进这里再排期。
>
> **一个重要背景发现**：2024–2026 年的 AI 工具站浪潮已把几乎所有「经典工具」
> 做成了「本地计算 + 免费 + 无水印 + 无注册」。**不要再押注「我们更干净」作为差异点**——
> 竞品已经干净了。差异化只剩三条路：①产物即内容（ASCII、二维码、词云）②工具集的
> 统一入口与可信品牌（ PlainKit 的根本策略）③工具间协同。选品时按这个顺序想。

## 一、已定（首批 / 排期中）

### 图片 → ASCII 字符画（工具 6，下一个做）

- **做什么**：上传本地图片（FileReader 纯本地解码），按亮度映射为字符画；可调列数密度、字符集（经典 / 方块 / 极简）、反相；复制纯文本 + 导出 PNG（monospace 渲染，解决手机聊天里等宽字体乱版的问题）
- **可分享产物**：产物即内容——ASCII 图发 Discord / README / 群聊；PNG 导出保证分享时不烂版
- **竞品（3 组关键词）**：imagetoascii.art（2026 新站，完成度极高：preset、TXT/PNG/SVG/ANSI 导出）、FreeMake.cc（4 种字符风格 + 本地处理）、toolshu.com/image2ascii、toolszone.net——**赛道饱和，且竞品已做到「本地+免费+无水印」**
- **裁决**：做。理由不是差异化而是**传播效率**：产物即内容 + 实现成本全站最低（亮度采样 + 字符映射，纯函数一天量）+ r/InternetIsBeautiful 调性契合。竞品饱和在「统一入口」策略下可接受（分组工具同样饱和，已验证走得通）
- **证伪条件**：上线发帖两周内零分享/零回流 → 「产物即内容」假设失效

### 二维码生成器（工具 7，ASCII 之后）

- **做什么**：网址 / 文本 / Wi-Fi 凭据 → 静态二维码；本地生成；PNG / SVG 导出；可调前景色（保持高对比度约束）
- **可分享产物**：产物=二维码本身，天然要印出去 / 发给别人；高频实用，是留存型工具（与 ASCII 的「一次性玩具」互补）
- **竞品（3 组关键词）**：qr-code-generator.com（老牌但有付费墙引导）、qrgenerators.dev / FreeToolPark / utilitytool.vercel.app（2026 新站，全部已主打「本地生成 + 无水印 + 免费」）
- **成本注意**：QR 编码算法（Reed-Solomon、掩码、版本选择）自研成本高。倾向引入 MIT 协议的 npm 依赖**打包进 bundle**（不违反「无第三方运行时脚本」——那是指外部 CDN 加载；但 Apache-2.0 NOTICE 合并义务触发，见 PROJECT-BRIEF §6.1 第 2 条）。s9 技术方案时定夺
- **裁决**：做，排 ASCII 之后。高频实用 + 产物即内容，竞品饱和但同样走「统一入口」逻辑
- **2026-09-24 s8 已定夺（用户裁定，覆盖上面的倾向）**：**自研编码核心**（只支持字节模式 UTF-8 + 固定 ECC M + 自动最小版本，目标 ≤3KB gzip），**引入 MIT 库仅作 devDependency 用于单元测试交叉验证**（不进 bundle，因此不触发 NOTICE 合并义务）。理由：工具页 JS 预算 ≤10KB gzip，qrcode-generator 解包 555KB / qrcode 135KB，取核心也会逼近红线；且「扫不出来的码」是二维码工具最致命的失败模式，正确性必须由黄金标准逐模块比对兜住

## 三、明确不进池（与产品概述 §6.4 一致 + 本次新增）

- 摩尔质量单独成工具——产物（`40.08 g/mol`）无人截图，**过不了可分享产物门槛**，已驳回
- Pomodoro / 计时器——无产物
- 密码生成器——产物无人分享
- 掷骰子 / 转盘——与随机分组抽签器重叠，且转盘动画违反 DESIGN.md 动效红线
- 梗图模板库——版权风险不可控
- 网速测试——需要带宽服务器，预算 0 扛不住
