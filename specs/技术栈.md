## 0. 一句话总览

**Astro（纯静态输出）+ TypeScript strict + 原生 CSS 变量 + Vitest，运行时依赖为零。**

`package.json` 的 `dependencies` 永远是 `{}`。所有依赖都在 `devDependencies`，全部是构建期工具，一行都不会进用户的浏览器。

## 1. 核心决策（为什么是这套）

### 1.1 需求分析：约束 → 技术要求

技术选型不是挑最热门的，是把硬约束翻译成技术要求。

| 项目硬约束（来自 PROJECT-BRIEF） | 对技术栈的强制要求 |
|---|---|
| 无后端 / 无数据库 / 无账号 | 运行时依赖必须是 `{}` |
| 所有计算在浏览器本地完成 | 计算逻辑必须是**纯函数**（确定性、可单测） |
| 首屏加载要快（硬指标） | 默认零 JS；零外部请求（无 web font、无 CDN、无分析） |
| 5 个工具 → 50+ 个页面共享外壳 | 外壳复用必须**机械化**，不能靠文档约束 |
| 代码要干净（开发者给星的理由） | TypeScript strict + 统一格式化 + 纯函数架构 |
| 可自托管（`npm run build` 出静态文件） | 构建产物必须是纯静态目录 |
| 每个工具有「可分享产物」 | 需要 URL 状态编码 + 客户端生成图片 |
| TDD 工作流（s11 是 RED→GREEN→REFACTOR） | 纯逻辑必须与 DOM **完全分离** |

### 1.2 最重要的一条架构决策

> **计算逻辑写成不碰 DOM、不碰浏览器的纯 TypeScript 模块。**

每个工具分成两层：

- **逻辑层** `src/lib/<tool>/` —— 纯函数。输入数据，输出数据。没有 `document`、没有 `window`、没有 `fetch`。用 Vitest 直接跑，不需要浏览器、不需要 DOM 模拟。
- **界面层** `src/pages/tools/<slug>/index.astro` —— 只负责「把 DOM 上的值读出来、交给逻辑层、把结果画回去」。

**这条决策同时解决两个问题**：① TDD 变得极低成本（纯函数测试，毫秒级）；② 用户「不读代码也能验收」——因为逻辑可以被单独喂输入、单独看输出。

### 1.3 为什么是 Astro 而不是原生 TS + Vite

备选方案是「原生 TS + Vite 多页面」，技术上完全可行，且零框架抽象、可移植性最强。最终选 Astro 的理由只有一条，但它是决定性的：

> **Astro 的 Layout 组件可以声明 TypeScript props 类型 —— 忘记传 `title` 或当前页标识，构建阶段直接报错。**
>
> 也就是说：**设计一致性从「文档约束」变成「编译期错误」。**

这个项目的实际情况是——用户不写代码，未来 12 个月内会有几十个独立对话各自新增工具。靠 `DESIGN.md` 的文档约定来维持外壳统一，**必然会漂移**；靠编译报错不会。这是唯一一条能机械化兜住「几十个陌生 Agent 各写各的页面」的机制。

附带收益（都免费）：

- **默认零 JS** —— 页面里不写 `<script>`，产物 JS 就是 0 字节
- **文件路由** —— 新增工具 = 新建一个文件，不需要在配置里登记路由
- **`dependencies: {}`** —— Astro 全部装在 devDependencies

必须诚实说清的代价：

- devDependencies 约 500+ 个包。**它们是构建期工具，不进产物、不进浏览器**，但确实扩大了供应链面，也让 `npm install` 慢一些。
- 构建产物在 `dist/`，部署到 GitHub Pages 的子路径时需要配 `base`。
- `.astro` 是 Astro 专有格式。可移植性不如纯 HTML，但 `.astro` 语法几乎就是 HTML + 前置脚本，任何 Web 开发者都能读懂。

## 2. 版本与锁定

| 项 | 版本 | 说明 |
|---|---|---|
| **Node.js** | **24 LTS** | `.nvmrc` 写 `24`；Cloudflare 构建环境变量 `NODE_VERSION=24`；`engines.node` 写 `>=22.12.0`（对自托管者宽松） |
| Astro | 7.x | 要求 Node `>=22.12.0`，24 满足 |
| TypeScript | 7.x | |
| Vite | 8.x | Astro 7 内置，不单独安装 |
| Vitest | 5.x | 要求 Node `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0` |
| Prettier | 3.x | 另需 `prettier-plugin-astro` |

**为什么锁 24 而不是 22**：Cloudflare Pages 构建镜像现在默认 22.16.0，22 满足所有依赖的最低要求。但 2026-09 时 Node 22 已进入维护期，24 是当前 Active LTS，且**与用户本机 nvm 的 v24.17.0 一致**——本地和 CI 用同一个大版本，少一类「本地能跑 CI 挂」的问题。

必须提交 `package-lock.json`，CI 用 `npm ci`。

## 3. 前端

### 3.1 框架

- **Astro 7**，`output: 'static'`（默认，纯静态）。**不要加任何 SSR 适配器**（`@astrojs/cloudflare` / `@astrojs/node` 等），那是给服务端渲染用的，本项目不需要，加了反而会破坏纯静态约束。
- `site`：正式域名确定后填入（当前 `https://plainkit.app` 为占位）。
- `base`：**由环境变量 `BASE_PATH` 控制**。Cloudflare Pages 用 `/`，GitHub Pages 镜像用 `/plainkit/`。同一份代码、两套部署，不改源码。
- `build.format: 'directory'` + `trailingSlash: 'always'` → URL 形如 `/tools/gpa-calculator/`，每个工具是真实静态路径，不是 hash 路由、不是 SPA。

### 3.2 样式

- **原生 CSS + CSS 自定义属性做 design tokens。**
- 全局：`src/styles/tokens.css`（颜色、间距阶、字号阶、圆角、阴影）+ `src/styles/base.css`（重置、排版基线、页面外壳）。
- 工具私有样式用 Astro 组件内的 `<style>`（Astro 自动加 scoped 属性，不会互相污染）。

**不采用 Tailwind，不采用任何 CSS 框架 / UI 组件库。** 理由：① 项目要求「克制、统一、可信赖」，Tailwind 会在 markup 里堆满 class 噪音，与这个目标直接冲突；② 多一层构建与配置；③ 对 50 个页面来说，一套写死的 tokens + 少量 scoped CSS 已经足够，且体积最小。

### 3.3 状态管理

**不引入任何状态库。** 每个工具的输入状态就是**浏览器 URL 的 query 参数**。这一点不是妥协，是设计：

> URL 参数化 = 「可复制链接」这个可分享产物的技术基础。

用户在工具里填的表单，序列化进 `?courses=...`，复制链接给别人，对方打开就是这个状态。不需要后端、不需要数据库、不违反「数据不出设备」。

### 3.4 字体

**系统字体栈，零 web font，零外部请求。**

理由：首屏速度是硬指标，而一个字体文件是真实的首屏成本。字体栈用系统原生（`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif` 这类）。

**一个必须知道的结果**：分享出去的卡片是 PNG，**在创建者的机器上渲染一次**，之后所有看到这张图的人看到的是同一张位图。所以「系统字体不一致」不会让分享产物不稳定——它只意味着不同人各自生成的卡片会有细微字形差异。

**由此产生一条实现要求**：卡片渲染器必须**基于测量的自适应排版**（先测文字宽度再决定换行/缩放），不能按固定像素绝对定位。否则某个系统字体更宽的用户会渲染出文字溢出的卡片。

### 3.5 图片生成（可分享产物）

**Canvas 2D 原生 API 手绘，零依赖。**

用于：倒计时/纪念日卡片、随机分组结果图。

实现要点（写下来避免以后返工）：

- 按 `devicePixelRatio` 放大画布（导出 2x/3x），保证手机上看清晰
- 用 `canvas.toBlob()` 导出 PNG
- 文字排版：先 `measureText` 再决定换行与字号，**不要假设固定宽度**
- 卡片必须带站点标识（项目已定规则：可分享产物强制带标识，形成回流闭环）
- 不要引入 `html-to-image` / `dom-to-image` / `satori` 之类的库：它们对 CSS 支持不完整、Safari 上坑多，还会打破「零运行时依赖」的叙事

## 4. 后端

**无。**

这不是「暂时不做」，是项目硬约束：没有服务器、没有 API、没有边缘函数、没有 Serverless。所有计算在浏览器完成，用户数据不离开设备。

→ 因此**不要引入 Cloudflare Workers / Functions、不要引入任何形式的服务端中间件**。Cloudflare Pages 在这里的角色只是静态文件 CDN。

---

## 5. 数据存储

**无。**

没有数据库、没有 `localStorage` 作为业务数据存储、没有用户账号、没有 Cookie 追踪。

工具状态只存活在 URL query 参数里（见 3.3）。

**唯一的例外**：允许用 `localStorage` 存纯界面偏好（例如「上次用的分组数量」），但必须是**可选的舒适性功能**，且不能是任何功能正常工作的前提。且不得含任何个人数据。默认不写。

## 6. 目录与文件约定（骨架，s4 会细化）

```
plainkit/
├── astro.config.mjs
├── vitest.config.ts
├── tsconfig.json            # extends "astro/tsconfigs/strictest"
├── .prettierrc
├── .nvmrc                   # 24
├── Dockerfile               # nginx:alpine 托管 dist/（自托管用）
├── docker-compose.yml
├── public/                  # 静态资源（favicon、og 图等）
└── src/
    ├── layouts/
    │   └── BaseLayout.astro      # 全站外壳：head / header / nav / footer
    ├── components/
    │   └── ToolShell.astro       # 工具页统一容器
    ├── styles/
    │   ├── tokens.css            # design tokens（DESIGN.md 定义具体值）
    │   └── base.css
    ├── lib/
    │   └── <tool-slug>/
    │       ├── index.ts          # 纯函数逻辑
    │       └── index.test.ts     # 同目录单测（Vitest 默认会捡到）
    └── pages/
        ├── index.astro           # 首页（工具索引）
        └── tools/
            └── <tool-slug>/
                └── index.astro   # 工具页
```

**约定**：

- 逻辑与测试**同目录**，文件名 `<模块>.test.ts`。这样「加了逻辑但没加测试」在目录里肉眼可见。
- 路径别名 `@/` → `src/`。
- 工具的 slug 与 URL 路径、目录名、`src/lib/` 下的目录名**四处必须完全一致**。这是唯一能靠命名兜住的东西，别让它漂。

## 7. 测试与验收策略

| 层 | 工具 | 覆盖什么 |
|---|---|---|
| 单元测试 | **Vitest** | `src/lib/` 下的纯函数逻辑。含边界情况（缺考、0 分、跨闰年、重复运行随机性等） |
| 浏览器验收 | **agent-browser skill**（项目工作流第三步） | 真的打开页面、真的输入、真的点、截图给用户看 |

**不引入 Playwright / Cypress 等 E2E 框架。** 理由：项目工作流已经规定了「用 agent-browser 实际打开页面操作并截图」这一步，它的职责与 E2E 框架重叠；自动化 E2E 会显著增加依赖、CI 时间和维护成本，而在 5–20 个页面的规模上收益不成立。

Vitest 配置：`environment: 'node'`（纯函数不需要 DOM），用 `getViteConfig` 与 Astro 共享配置。

> **红线**：`src/lib/` 下的任何文件都不允许出现 `document` / `window` / `navigator`。一旦出现，说明逻辑与界面耦合了，TDD 就废了。

## 8. 依赖政策

1. **`dependencies` 永远为空。** 所有依赖在 `devDependencies`。
2. **新增任何依赖前必须先问用户。** 包括「只是想省点代码」的小库。
3. 判断标准：**这个库能不能被 30 行原生代码替掉？** 能，就别加。首批 5 个工具全部能靠原生 API 完成。
4. 如果确实必须加（例如第二阶段的 PDF 库），规则是：**按页面动态引入**，不让它进入首页或其他工具的加载路径。

## 9. 基础设施与工具

| 项 | 选择 | 说明 |
|---|---|---|
| 包管理 | **npm** | 用户机器上已有；pnpm 需额外安装，不值得 |
| 构建命令 | `npm run build` | 产物 `dist/` |
| 主站托管 | **Cloudflare Pages** | 构建命令 `npm run build`，输出目录 `dist`，环境变量 `NODE_VERSION=24`、`BASE_PATH=/` |
| 镜像托管 | **GitHub Pages** | 通过 GitHub Actions 构建并发布，`BASE_PATH=/<repo>/` |
| CI | **GitHub Actions** | 顺序：`format:check` → `typecheck` → `test` → `build`。**任一环节失败则不允许合并** |
| 自托管 | **Dockerfile + docker-compose.yml** | `nginx:alpine` 托管 `dist/`，`docker compose up` 即可跑起来 |

Cloudflare Pages 免费额度（够用，记录备查）：每月 500 次构建、单次构建 20 分钟上限、单个站点 20,000 个文件。

## 10. 性能预算（初值）

> **本节的具体数字由 `DESIGN.md` 最终定死并负责执行。** 这里给出初值和「技术栈层面必须做到的事」。

| 指标 | 初值 | 说明 |
|---|---|---|
| 单页 JS（gzip） | ≤ 30KB | 不含某个工具专属的重型库；首批 5 个工具的目标是 **< 10KB** |
| 单页 CSS（gzip） | ≤ 15KB | |
| 外部请求 | **0** | 无字体、无 CDN、无分析、无第三方脚本 |
| LCP | < 1.0s（中端 4G） | |
| 首页 JS | **0 字节** | 首页是纯索引，不写 `<script>` |

**一条硬规则**：任何导致「页面在初始加载时发起对外部域名的请求」的改动，一律拒绝。这是「无追踪 + 本地计算」这个卖点的技术底线。

## 12. 明确不采用的东西（及原因）

**这一节是给未来的 Agent 看的。「不要自创流程」同样适用于技术栈。**

| 不采用 | 原因 |
|---|---|
| React / Vue / Svelte / Solid | 重框架，需要客户端运行时；本项目是纯静态多页面工具站，用不上 |
| Next.js / Nuxt / SvelteKit | 带 SSR/Node 运行时假设，与「无后端」硬约束冲突 |
| Tailwind / Bootstrap / 任何 UI 组件库 | 与「克制、统一、可信赖」冲突；体积与 class 噪音 |
| 任何状态管理库 | URL query 参数已经解决全部状态问题 |
| 任何动画库（GSAP / Framer Motion 等） | 项目硬约束：动效只允许结果出现时的轻微过渡，用 CSS 原生做 |
| Web font（Google Fonts / 自托管字体文件） | 首屏性能红线；系统字体栈足够 |
| 任何分析 / 埋点 / 错误上报 SDK | 直接违反「零追踪」 |
| 任何服务端中间件、Serverless 函数、Workers | 直接违反「无后端」 |
| Playwright / Cypress | 与 agent-browser 验收步骤职责重叠，成本不划算 |
| `html-to-image` / `satori` 等卡片生成库 | 打破零依赖叙事；Canvas 2D 原生足够 |
| i18n 框架（i18next 等） | 英文界面优先，第一版不做多语言切换；文案直接写英文，第二期再抽 |
| `dependencies` 里的任何东西 | 运行时依赖为零是硬规则 |
